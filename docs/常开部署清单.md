# 常开部署清单

Agent Relay 是多平台节点的任务协作中心：局域网内所有连得上服务的节点都可能在任何时候领取、交付或等待任务。中心停了，所有节点一起停。本清单列出让中心**常开、够得着、可恢复**需要逐项确认的事，适用于 v0.5.0 起在 Windows + WSL + Podman 上的部署。

每一项都写了怎么核对。清单只说明要做到什么，不代表任何一台机器已经做到；部署方按实际结果逐项打勾，并把结论记入部署记录。

## 一、升级前

| 项 | 要求 | 核对 |
| --- | --- | --- |
| 备份 | 升级前用同进程备份做一份，并确认可恢复 | `upgrade-control backup` 后运行 `ops/verify-backup.py`，见[运维与升级](运维与升级.md) |
| 数据格式 | v0.5.0 使用新任务流程后写入 `min_reader: 7`，登记执行环境后至少为 6；v0.4.x 打不开。v0.5.1 保存项目能力目录后写入 `min_reader: 8`，v0.5.0 打不开。回退只能靠备份 | 升级后 `taskpool.py inspect-store` 查看 `format.min_reader` |
| 构建核对 | 记录镜像 ID、构建包 SHA256 和源码提交 | `python -B build.py`，`ops/verify-release.py` |

## 二、常开

容器的 `--restart unless-stopped` 只在 Podman 自身运行时生效。Windows 重启、WSL 被关闭或空闲回收后，容器不会自己回来，需要下面三层都接上。

| 项 | 要求 | 核对 |
| --- | --- | --- |
| WSL 随 Windows 启动 | 用 Windows 计划任务在开机（不必登录）时启动一次 WSL 发行版，例如运行 `wsl.exe -d <发行版> --exec /bin/true` 后保持 systemd 服务 | 重启 Windows，不登录，从另一台节点访问 `/readyz` |
| WSL 不被空闲回收 | WSL 在没有前台会话时可能被关闭；在 `%UserProfile%\.wslconfig` 设置 `vmIdleTimeout=-1`（WSL 2 新版本支持），或由上一项的计划任务保持一个常驻进程 | 关闭所有终端 30 分钟后访问 `/readyz` |
| 容器随 WSL 启动 | WSL 开启 systemd（`/etc/wsl.conf` 中 `[boot] systemd=true`），按运行容器的身份配置：rootful 在 WSL root 下运行 `systemctl enable podman-restart.service`；rootless 由容器所属用户运行 `systemctl --user enable podman-restart.service`，并启用 `loginctl enable-linger <用户>` | rootful 用 `systemctl is-enabled podman-restart.service`，rootless 用 `systemctl --user is-enabled podman-restart.service` 和 `loginctl show-user <用户> -p Linger`；`wsl --shutdown` 后重新进入，以同一身份运行 `podman ps` 确认容器为 Up |
| 健康检查 | 定期探测 `GET /readyz`，返回 200 为可接收请求；维护阶段返回 503 属正常 | 部署方的监控或计划任务每分钟探测一次，连续失败时通知负责人 |

## 三、够得着

| 项 | 要求 | 核对 |
| --- | --- | --- |
| 固定地址 | 服务所在 Windows 的局域网地址固定（DHCP 保留或静态地址）。地址变化会让端口转发、防火墙规则和节点保存的入口同时失效 | 路由器 DHCP 保留列表；`ipconfig` |
| 端口转发 | Windows TCP 18443 转发到 WSL 回环 18765，由 `ops/Set-LanIngress.ps1` 建立；跨网段节点用 `ops/Set-EasyTierIngress.ps1` | `netsh interface portproxy show v4tov4`；从另一台节点访问 `https://<地址>:18443/readyz` |
| 证书 | 证书服务名与节点使用的名称一致，节点按 `dist/taskpool-lan-cert.pem` 的 SHA256 核对。更换证书后，所有节点的邀请和入口要重新分发 | 客户端 `whoami` 不报证书错误 |
| 窗口接入 | 新节点优先用「平台接入点」申请、负责人同意，不再逐个发邀请链接 | 「窗口管理 → 节点总览」能看到新窗口 |

## 四、可恢复

| 项 | 要求 | 核对 |
| --- | --- | --- |
| 定时备份 | 用 `ops/install-local-backup.sh` 在 WSL root 下安装系统级 `taskpool-local-backup.timer`（每天 03:30 香港时间）| `systemctl is-enabled taskpool-local-backup.timer`；`systemctl list-timers --all taskpool-local-backup.timer` |
| 异机副本 | 本机备份不防硬盘损坏；至少每周把备份复制到另一台机器或外部存储 | 部署记录中的最近一次异机复制时间 |
| 恢复演练 | 每次大版本升级后，在独立目录用备份恢复一次并启动服务 | `ops/verify-backup.py` 和一次实际启动 |

仓库备份安装器把单元写入 `/etc/systemd/system/`，备份服务操作 rootful Podman 的固定容器；不要用 `systemctl --user` 查询它，也不要将此安装器直接用于 rootless 容器。rootless 部署需要另行适配备份服务和权限，并验证恢复。

## 五、读写速度

v0.5.0 起服务只读取上次之后新增的账本记录，已核对过的记录凭文件名、大小、修改时间、变更时间和 inode 确认未被改动，有任何不符就重新完整核对整条哈希链。服务重启后的第一次读取仍是完整核对。

收件记录（每个写请求一份）同样只核对新增的文件。

实测（Linux ext4，Python 3.13，每个任务约 4 条账本记录）：

| 账本记录数 | 完整读取 | 增量读取（无新记录） | 一次写入 |
| --- | --- | --- | --- |
| 约 800 | 139 毫秒 | 7 毫秒 | 104 毫秒 |
| 约 2000 | 377 毫秒 | 24 毫秒 | 290 毫秒 |
| 约 4000 | 725 毫秒 | 60 毫秒 | 592 毫秒 |

增量读取仍随状态大小增长，因为每个请求拿到的是独立副本；写入仍需重算候选状态。账本过万条后应再评估。
