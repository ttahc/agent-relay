# 内网任务服务升级操作

本机数据合同版本为 2。项目使用稳定编号和显示名称，窗口使用独立凭据与固定编号，任务合同保存迭代目标、前后任务、交付物、能力要求及独立性策略。原有任务、领取、输入、交付和回执从同一账本回放。迁移会将 T02 设为待启动，并绑定当前升级收口。

项目成员的角色为 manager、executor、receiver。人员账号在窗口目录登记执行端后得到独立凭据和窗口编号。把页面给出的编号放入对应聊天标题，可从任务详情或窗口目录查询。原有人员或执行端需由管理员依据实际归属绑定，项目授权在对应项目办理。能力记录按项目和身份保存，已验证能力由项目管理者或接收者凭实际证据登记。

网页入口位于项目、窗口目录、能力与证据、状态追溯和升级验收。任务登记保存为待启动，详情页展示匹配结果和阻塞原因。执行端可以使用相同凭据调用 API。迁移后的请求保留稳定 request_id，状态不明时读取回执或重试原请求。

| API | 用途 |
| --- | --- |
| `GET /v1/projects`、`GET /v1/projects/{id}` | 查看项目及成员授权 |
| `GET /v1/identity`、`GET /v1/executors` | 查看身份绑定、窗口编号和领取 |
| `GET /v1/capabilities?identity=...` | 查看适用的能力及证据版本 |
| `GET /v1/tasks?project=...` | 获取对本身份可领取的任务 |
| `GET /v1/tasks/{id}`、`GET /v1/audit?task=...` | 查看合同、匹配结果及事件时间线 |
| `GET /v1/receipt?request=...` | 查询当前身份的原请求回执 |
| `GET /v1/wait?cursor=...&timeout=...` | 保持请求直到本身份的待处理事件变化（v0.4.2 起，最长 50 秒） |
| `POST /v1/window-apply` | 窗口凭平台接入点的申请码提交申请或查询结果；负责人在网页同意后才登记（v0.4.3 起，免登录，申请不写台账） |
| `GET /workspace-state?revision=...&timeout=...` | 网页工作台用：登录会话保持请求直到所见任务状态变化（最长 50 秒，每人 2 个）；不带 `timeout` 时立即返回当前摘要 |
| `POST /v1/executor-enroll`、`POST /v1/executor-sync` | 登记或续接窗口 |
| `POST /v1/capability-save`、`POST /v1/project-grant` | 写入能力或授权版本 |
| `POST /v1/task-publish`、`POST /v1/task-hold`、`POST /v1/task-scope` | 按版本开放、等待或调整任务范围 |
| `POST /v1/task-interrupt`、`POST /v1/task-recover` | 记录中断并核对实际停止及接续材料 |
| `GET /v1/upgrade`、`POST /v1/release-accept`、`POST /v1/release-close` | 查看当前发布合同、独立验收及收口 |

登记要求由 `requirements` 数组表达，每项包含 id、kind、value、required 和 evidence。必需的环境能力要求 verified，业务能力按任务指定的最低证据等级匹配。以网页登记页或升级验证脚本中的完整请求为样例。额外客户端时间通过 `X-TaskPool-Reported-At` 提供，时间线同时保留服务收到及提交的时间。

运行容器为 `intranet-task-pool-local`，固定服务名为 `taskpool.test`。实际有线及 EasyTier 地址见部署记录。公开证书为 `dist/taskpool-lan-cert.pem`，客户端在更新证书后按其 SHA256 核对。服务通过 Windows 的 TCP 18443 转发到 WSL 回环 18765。

在管理员 PowerShell 中启用或核对 EasyTier 入站规则。

```powershell
& '.\ops\Set-EasyTierIngress.ps1' -Action Enable -InterfaceGuid <网卡GUID> -Address <虚拟IPv4> -Subnet <虚拟网段CIDR>
& '.\ops\Set-EasyTierIngress.ps1' -Action Check -InterfaceGuid <网卡GUID> -Address <虚拟IPv4> -Subnet <虚拟网段CIDR>
```

网卡 GUID 可用 `Get-NetAdapter -IncludeHidden | Select-Object Name, InterfaceGuid` 查询。该脚本按接口 GUID 核对 EasyTier 虚拟网卡（名称以 `et_` 开头）、虚拟地址及直连网段，启用时限定本机 EasyTier IPv4 地址、TCP 18443、虚拟网卡和来源网段。撤销该入站规则时执行 `-Action Disable`。真实对端验证使用 `ops/verify-peer.py`，在具备独立网络来源的设备上核对 TLS、登录、领取、交付、停止及请求回执。

升级脚本为 `ops/upgrade-local.sh`。脚本在原服务退出后生成全卷备份和逐文件清单，比较还原卷的内容及文件权限，校验原任务输入与编号，再在还原卷追加数据合同与 T02 待启动记录。老镜像读取升级卷时应停止回放。部署记录包含镜像、卷、备份摘要及迁移检查，备份本身保存在 WSL 私有目录。

服务进入维护或回切前先核对活动领取和待恢复请求。原容器与原数据卷用于对应恢复点。候选卷已有业务写入时，由操作人员保留新记录并按可验证的数据版本决定修复或恢复。恢复后核对账号、任务、文件指纹、请求回执和窗口编号高水位，再开放写入。

T02 的开工校验要求当前镜像的升级验收、收口和证据指纹成立，接收者已确认并有项目授权。升级接收者核对实际运行报告，管理员完成收口和任务发布。
