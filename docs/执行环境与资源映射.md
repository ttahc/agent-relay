# 执行环境登记与目录互斥（阶段 1、2）

## 模型与边界

- 平台、AI 窗口、执行环境是三件事。平台名称及原有 `config.environment` 只是来源描述；不会证明两个窗口相同、不同或隔离。
- 一个窗口可选择多个执行环境；一个环境可绑定多个窗口，包括来自不同平台的窗口。`local`、`cloud`、`container`、`remote`、`unknown` 是环境种类说明，不是锁域或权限。
- 环境编号由系统管理员登记，窗口只可在自己的新执行配置中选择已绑定的环境。已有配置、执行段、动作和占用不会随默认配置切换而改写。
- 资源映射将某环境的逻辑 `domain` 对应到**服务端可核实的目录根**，或**管理员明确核实的全局物理存储域**。`path:work/item` 对应根下的 `work/item`。物理文件身份、目录祖先和规范路径决定冲突，映射名称与平台名称不决定冲突。两个映射可指向同一目录。
- 项目角色、任务资源上界、窗口/负责人的资源权限和窗口并发上限照常检查。环境绑定和物理映射不授予任何这些权限。

本阶段支持两种证据来源：服务端实际可见目录的文件系统证明，以及管理员核实的全局物理存储域。后者可用于没有挂载到服务端的远端节点：两个已确认独立的存储域可并行，共享域中的路径写入保守串行（读取之间可并行）。一个节点可访问多个域，多个节点也可共享一个域，域不是机器名。

远端的独立性是管理员对真实拓扑的明确确认，**不是服务自动探测或验证了远端文件系统**。登记人须核对共享盘、容器挂载、工作树、硬链接及路径别名；共享资源使用同一个域或合并已有域，不能靠改名声明独立。错误的独立性确认可能造成实际冲突，服务无法在没有受信远端探测的情况下自动发现。这是本阶段明确的信任边界。

没有物理证明也没有管理员确认映射的路径，仍沿用本服务已有的保守互斥：任意未知路径与路径写入冲突。不会把所有注册节点无差别串行，也不会把不同自报域当作隔离证明。旧的无域占用可能暂时阻挡各域，须按原流程核实停止后归还。应用/设备资源保留原有规则；自动远端探测适配器和应用实例登记不在本阶段内。

## 管理员登记

先备份数据并停止服务。本机命令沿用现有管理员身份与独占账本机制，不产生新凭据，也不打开第二个在线写实例。

环境文件 `environment.json`：

```json
{
  "environment_id": "local-copy-a",
  "version": 0,
  "label": "本机独立工作副本 A",
  "kind": "local",
  "executors": ["已登记窗口的身份编号"],
  "active": true
}
```

```sh
python -B taskpool.py --store local environment-save --request-id register-copy-a --config environment.json
```

映射文件 `mapping.json`：

```json
{
  "environment_id": "local-copy-a",
  "domain": "workspace",
  "version": 0,
  "root": "/absolute/service-visible/copy-a",
  "active": true
}
```

Windows 使用真实绝对目录，例如 `C:\\workspaces\\copy-a`。

```sh
python -B taskpool.py --store local resource-map-save --request-id map-copy-a --config mapping.json
```

`version: 0` 用于新记录；修改使用当前版本号。变更必须使用新的稳定 `request_id`；响应不明确时先按原编号重试，不能把原请求号用于不同内容。管理员也可通过已有认证写接口调用 `POST /v1/environment-save`、`POST /v1/resource-map-save`（下节的存储域登记/合并同样使用对应 `/v1/` 写接口），字段与 JSON 一致并增加 `request_id`；非管理员被拒绝。

目录映射的根在登记时解析为真实目录，并冻结设备/文件身份。根目录的符号链接别名会归一到同一真实根；资源路径内部的符号链接或重解析点拒绝取得证明，需使用明确可信根或隔离副本。目录资源还冻结其最多 4096 个后代的文件身份，以识别树内硬链接及挂载别名；遇到树内链接、无法读取或超出预算时，不使用不完整证明，而退回保守互斥。开始前会复核完整证明。根目录无法探测时不能登记新映射。

将 `active` 改为 `false` 可停用环境或映射。停用既有映射时 `root` 字段仍须提供，但可为空，服务保留其原目录记录，不要求已失联的目录重新可访问。更新记录保留历史版本，旧占用的物理证明不改变。排队申请若绑定已停用/变更的映射会阻止授予；旧动作不得借新映射开始。已授予、已开始或结束未确认的占用仍须走原停止/归还流程，不会自动释放。

## 远端节点与全局存储域

管理员先确认一个新的物理存储范围与所有现有独立域无共享的可写物理对象；若实际共享，直接引用已有域。登记文件 `storage-a.json`：

```json
{
  "storage_domain_id": "node-a-private-copy",
  "label": "节点 A 的独立工作副本",
  "independent": true,
  "evidence": {"note": "说明核对了哪些实际挂载、工作副本和别名，以及为何与已有域独立", "sha256": "核实材料的64位SHA256"}
}
```

```sh
python -B taskpool.py --store local storage-domain-register --request-id domain-copy-a --config storage-a.json
```

域身份不可复用、改写或拆分。`independent: true` 不是默认值，必须由管理员明确确认。接着使用原 `environment-save` 登记节点的实际执行环境，再写 `remote-mapping.json`：

```json
{
  "environment_id": "remote-instance-a",
  "domain": "workspace",
  "version": 0,
  "root": "",
  "active": true,
  "mapping_kind": "attested-domain",
  "storage_domain_id": "node-a-private-copy",
  "evidence": {"note": "说明本执行环境的 workspace 实际对应哪个已核实物理存储域", "sha256": "映射核实材料的64位SHA256"}
}
```

```sh
python -B taskpool.py --store local resource-map-save --request-id map-remote-a --config remote-mapping.json
```

这里不读取服务端目录，也不把远端的 inode 或主机内路径当作全局身份。相同域内，即使两个窗口申报了不同逻辑路径别名，路径写入也互斥；不同已确认域可并行。同一全局域也可同时用于 `server-local` 映射，只须在原目录映射 JSON 中加 `storage_domain_id`。已观察到的本地物理别名仍优先判为冲突，不会因独立域标签不同而放行。若全局域已知的本地目录范围重叠，服务拒绝把它们登记为独立域，须先明确合并。远端动作的证明还会带上同域中可见本地映射的最新物理范围，并在开始前复核，避免通过远端别名丢掉已知本地共享关系。范围无法完整读取时退回保守互斥。

发现两个域实际共享时，管理员用 `storage-domain-merge` 合并等价关系，配置包含 `storage_domain_id`、`other_domain_id`、`version`（管理员 `execution` 响应的 `storage_domain_revision`）及 `evidence`。合并只扩大保护范围，不删除旧域，不改写旧动作，不释放任何占用，并返回 `affected_grants`。合并后的旧授权在开始前重新检查冲突。若已有实际运行，管理员须核实并安排停止或隔离，合并不会自动终止外部进程。

既有映射不能切换到非等价域或删除其域绑定来绕过旧锁。等价关系可传递合并，不提供拆分接口。真正新的物理副本应单独核实为新资源；不能将旧共享存储冒充新副本。所有操作仍受现有管理员认证和请求回执机制约束，不生成新的运行凭据。

## 窗口选择与执行

服务启动后，窗口沿用原凭据：

```sh
python -B ops/round-client.py --state window.json execution
python -B ops/round-client.py --state window.json context save --environment-id local-copy-a --adapter manual --make-default
```

`execution` 返回有权查看的环境和映射编号/版本，不返回服务端绝对路径或文件身份。`context save` 未指定 `--environment-id` 时沿用所选配置的绑定；传空字符串可为新配置明确清除绑定（退回保守互斥，不解除旧锁）。原 `--environment` 继续是描述文字，不能代替实例编号。

后续仍使用原来的 `claim`、`segment open`、`action prepare --domain workspace --write path:work/item`、`resource request`、`action start`、事实与归还流程。客户端只取得许可，不自动运行程序。改变映射、环境授权、文件身份或父目录后，旧动作的开始许可会被拒绝；先核实实际工作与原占用，再建立新动作。

## 第一批验收

1. 同一负责人、相同权限和相同平台的两个窗口分别绑定两个独立目录或两个管理员确认的远端独立存储域，申请同一个逻辑资源名，应同时获授并可各自开始。
2. 两个环境（可来自不同平台）映射到同一物理目录，申请相同资源，应只有一个获授，另一个排队。根目录别名、同一文件的硬链接和目录祖先关系也不能绕过互斥。
3. 旧客户端不传环境编号时继续原行为；已有未知占用不能借登记新环境被清除。窗口改名、换模型或换默认环境不改写旧动作。

运行：

```sh
python -B verify_environment_domains.py
python -B run_checks.py
```

需要 Python 3.13+。完整存储与 HTTP 验收仍需 NTFS/ext4 和允许本机监听的运行环境。新版本可读取旧账本、服务旧客户端；使用新增登记或新版物理证明后，库会记录 `min_reader: 6`（执行协议仍为 5），旧程序必须拒绝打开，避免重放历史效果后按旧规则误判锁。不要用旧源码回放/启动该库；回退必须按备份恢复流程处理，不能只替换程序文件。管理员应保留与账本匹配的源码包和指纹。
